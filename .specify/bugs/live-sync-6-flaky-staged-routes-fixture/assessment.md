# live-sync-6: flaky test_actual_websocket_realtime_failure_soft_recovers_without_app_close
Symptom: Cloud CI run 38079033805 attempt 1 (main b40506f) failed in the compatibility suite. The call summary read back as '' (the column default) after the stream stopped, even though the poll loop had already seen the soft-recover interruption record. Reproduced on the box at 4 in 80 runs under CPU load.
Root cause: the staged_routes fixture used in-memory SQLite with StaticPool, so every session in both the test thread and the TestClient app thread shared ONE DBAPI connection. The test's poll read the app's uncommitted, autoflushed UPDATE (record_call_interruption -> _persist_escalation, before s.commit()). Then its session close() issued ROLLBACK on the shared connection, discarding the app's in-flight transaction.
Production: models.engine uses the default pool (separate connection per session), and writers use `with SessionLocal() as s: ... s.commit()`. So this cross-session rollback cannot happen in production. There is no production code race; the defect is in the test harness.
