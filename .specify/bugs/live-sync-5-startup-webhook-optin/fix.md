# Fix
Startup webhook configuration is now opt-in through ENABLE_STARTUP_TWILIO_WEBHOOK_CONFIG, default false. Only an explicit "true" (case-insensitive) enables it. When it is off, render_prepare emits TWILIO_VOICE_WEBHOOK_SKIPPED_STARTUP_OPT_IN_DISABLED, makes no carrier call and cannot fail start for webhook reasons. When it is on, the previous fail-closed behaviour is unchanged. The operator CLI `python provider_webhooks.py` is unchanged and remains the deliberate path. .env.example documents the flag. No env, secret or server change; live env does not set the flag, so live behaviour after a future deploy = no webhook mutation.
